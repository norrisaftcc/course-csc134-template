Reading 1 gave you one tool: a chain that checks ranges top to bottom. This page adds the other two — a cleaner way to match exact values, and a way to require two things at once.

Many exact matches: switch

A chain of else-ifs comparing the same variable against a list of exact values gets noisy fast. When you are matching one whole number against fixed choices — a menu, a class number — switch says it more cleanly. The gatekeeper's first question is exactly this shape.

#include <iostream>
using namespace std;

int main()
{
    int characterClass = 0;   // 1 = Warrior, 2 = Mage, 3 = Rogue
    cout << "Your class? (1 = Warrior, 2 = Mage, 3 = Rogue): ";
    cin >> characterClass;

    switch (characterClass)
    {
        case 1:
            cout << "\"A Warrior. Strong arms, I hope.\"\n";
            break;
        case 2:
            cout << "\"A Mage. A sharp mind, I hope.\"\n";
            break;
        case 3:
            cout << "\"A Rogue. Hands where I can see them.\"\n";
            break;
        default:
            cout << "\"I do not know that class. Off you go.\"\n";
    }

    return 0;
}

Compile it and type 2. The prompt and the answer land on the same line, because your keystroke echoes where the cursor already is:

Your class? (1 = Warrior, 2 = Mage, 3 = Rogue): "A Mage. A sharp mind, I hope."

Now run it again and type something the switch has never heard of — 9. It does not crash, and it does not silently do nothing:

Your class? (1 = Warrior, 2 = Mage, 3 = Rogue): "I do not know that class. Off you go."

Three parts to notice. case 1: is the value to match — with a colon, not a semicolon. break; stops the switch so it does not keep running into the next case. And default: is the catch-all when nothing matched — the gatekeeper's answer for a class she does not recognize.

Always give a switch a default. It is the safety net for input you did not plan for, and an unknown answer ending the program with a clear sentence is correct behavior, not a crash. Hold onto that break; — it comes back as Trap 2 in Reading 3.

Combining conditions: &&, ||, !

Sometimes one comparison is not enough. A middling Rogue can still slip through if she is strong enough and she brought a lockpick. Two conditions, both required. That is what these three operators are for.

&& AND — true only when both sides are true
|| OR — true when at least one side is true
! NOT — flips true to false 
// Both must be true:
if (strength >= 40 && hasLockpick)

// At least one is enough:
if (characterClass == 1 || characterClass == 2)

// Flip it — true when NOT locked:
if (!isLocked)

Caution

You cannot write if (strength >= 40 && >= 70). Each side of && must be a complete condition with its own variable: if (strength >= 40 && strength <= 70). Leaving out that second strength is a Static semantic error — the grammar is fine, the meaning is impossible — and the program will not compile until you fix it.

Nested conditions, and the whole gate

"Nested" just means one decision lives inside another. Only a Rogue is even asked about a lockpick, so that question sits inside the check for who you are. Here is the full scene, putting the switch, the nesting, the compound condition, and the outcome chain together.

Predict first. The player is a Rogue, strength 55, and answers 1 — yes, they have a lockpick. Which single line of outcome prints? Decide before you read past the code.

    bool hasLockpick = false;
    if (characterClass == 3)          // nested: only a Rogue is asked
    {
        int answer = 0;               // 1 = yes, anything else = no
        cout << "Do you carry a lockpick? (1 = yes, 0 = no): ";
        cin >> answer;
        hasLockpick = (answer == 1);
    }

    if (strength >= 70)
    {
        cout << "The gate swings wide. Go through.\n";
    }
    else if (strength >= 40 && hasLockpick)   // compound: BOTH must be true
    {
        cout << "Not strong, but those clever hands might do.\n";
    }
    else if (strength >= 40)
    {
        cout << "Borderline. Answer my riddle and the gate is yours.\n";
    }
    else
    {
        cout << "Too weak, and no trick to make up for it. Turned away.\n";
    }

Have your answer? Read on.

It prints: Not strong, but those clever hands might do.

Walk it. 55 is not 70 or more, so the first branch is skipped. Then 55 is 40 or more and the lockpick is true — so the whole compound is true and this branch wins. The chain stops there; the plain 40-or-more branch below never gets a look. Change that answer to 0 and the lockpick half fails, so the compound fails, and the next branch — the riddle — runs instead. Same strength, different ending, because of one condition. That is the whole point of M4.

Notice the order, because it is the trap hiding in plain sight: the lockpick branch sits above the plain 40-or-more branch. Flip those two and a Rogue with a lockpick would match the plain branch first and never reach the shortcut. A branch that can never run is a Logic error, not a style nit.
