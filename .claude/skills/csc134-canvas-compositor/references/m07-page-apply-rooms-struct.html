Module 07 · Apply

Your dungeon currently keeps its rooms in three separate arrays that have to stay in step with each other. Today we collapse them into one array of rooms. Most of the program is written below; one piece is yours.

The problem with three arrays

Here is what you have been working with since Module 6. Three arrays, and the only thing tying them together is that you agreed to use the same index in all three:

Read it in columns, not rows. Column 2 is one room, spread across three arrays: the name in one, the gold in another, the locked flag in a third. The room does not exist anywhere as a single thing. It exists as an agreement about the number 2.

Now insert a new room between the Cave and the Hall. You have to shift three arrays, identically, in the same direction, by the same amount. Miss one and the Hall's gold now belongs to a room it was never in. Your program still compiles. It still runs. It is simply wrong, quietly, and it will stay wrong until someone notices the numbers don't add up — that's a logic error, the fourth word in our taxonomy and the only one no tool will find for you.

This is not a mistake you made. Parallel arrays were the right tool for Module 6, when the only thing you had was arrays. The pain you just read about is the reason the next tool exists.

One box per room

A struct lets you say that these three pieces of data are one thing:

Same three values, one box. Now there is exactly one array, the fields travel together, and inserting a room moves all three pieces at once because they were never apart. You cannot half-update a room any more — not because you got more careful, but because the shape of the data stopped allowing it. That is what picking a better structure buys you: not less typing, fewer ways to be wrong.

Build it — one piece is yours

Type this into rooms.cpp. It is complete except for the TODO, which is the part you write:

#include <iostream>
#include <string>
using namespace std;

const int ROOM_COUNT = 3;

struct Room
{
    string name;
    int gold;
    bool locked;
};

int main()
{
    Room rooms[ROOM_COUNT];

    rooms[0] = {"Cave", 10, false};
    rooms[1] = {"Hall", 0, false};
    rooms[2] = {"Vault", 250, true};

    int totalGold = 0;

    for (int i = 0; i < ROOM_COUNT; i++)
    {
        cout << i << ": " << rooms[i].name;

        if (rooms[i].locked)
        {
            cout << " (locked)";
        }

        cout << " - " << rooms[i].gold << " gold" << endl;

        // TODO: add this room's gold to totalGold,
        //       but only if the room is not locked.
    }

    cout << "Reachable gold: " << totalGold << endl;

    return 0;
}

The dot in rooms[i].gold is the only new punctuation on this page. Read it right to left: the gold, of the room, at index i. Build it with g++ -std=c++17 -Wall -Wextra rooms.cpp -o rooms and run it before you touch the TODO:

0: Cave - 10 gold
1: Hall - 0 gold
2: Vault (locked) - 250 gold
Reachable gold: 0

Zero warnings, and a wrong answer. There is gold in two rooms you can walk into, and the program says nothing is reachable. Nothing is broken in any way a tool can see — the total is zero because nobody ever added to it. Look at that last line and then look at the TODO: that gap is the entire bug. Fill it in, rebuild, and the number you are aiming for is 10: the Cave's gold, plus the Hall's nothing, and not one coin from the locked Vault.

The numbering here is interesting. The rooms print as 0, 1, 2 — not 1, 2, 3 — because the index is where a thing sits, not which one it is. Change the cout to print i + 1 and run it. The display should change; rooms[i] must not. Mixing up those two is the most common way an array program goes wrong with the compiler saying nothing at all.

Caution — the common one

Most students who break this program break it by writing rooms.gold[i] instead of rooms[i].gold. The old habit is hard to shake, because in the parallel-array version the array name really did come first. This one the compiler will catch, and the error reads request for member 'gold' in 'rooms', which is of non-class type 'Room [3]'. Translated: you asked a whole array for a field, and only one room has fields. When you see non-class type, check the order of your brackets and your dot.

Before you start the lab

  • It builds with -Wall -Wextra and prints no warnings.
  • My last line reads Reachable gold: 10.
  • I set the Vault's locked to false, reran it, got 260, and set it back.
  • I added a fourth room and changed ROOM_COUNT to match, and it still works.
  • I can say out loud what rooms[i].gold means, in that order.
