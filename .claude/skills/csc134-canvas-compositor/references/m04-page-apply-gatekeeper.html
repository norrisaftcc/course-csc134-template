Module 04 · Apply

We build the gatekeeper together, in three stages. Every stage compiles and runs before we add the next one, so when something breaks you know it broke in the last five lines you typed. Type it yourself — do not paste.

Note

Two kinds of computer text on this page. A gray bar means this is exactly what your machine printed — the compiler, or your own program running. A green bar with a rose is Haiku, an AI assistant. Haiku is usually right and never authoritative — the rose means the checking is yours to do.

Stage 1 — who's there?

One question, one answer, and a switch that says something different depending on what came back. Start a file called gatekeeper.cpp and type this:

#include <iostream>
using namespace std;

int main()
{
    int playerClass = 0;

    cout << "1 = Warrior, 2 = Mage, 3 = Rogue" << endl;
    cout << "What are you? ";
    cin >> playerClass;

    switch (playerClass)
    {
        case 1:
            cout << "A Warrior. She looks at your arms." << endl;
            break;
        case 2:
            cout << "A Mage. She checks your hands for ink." << endl;
            break;
        case 3:
            cout << "A Rogue. She counts her keys." << endl;
            break;
        default:
            cout << "She has no idea what you are." << endl;
    }

    return 0;
}

Build it with g++ -std=c++17 -Wall -Wextra gatekeeper.cpp -o gatekeeper and run it. Answer 2. You should see exactly this, and nothing else:

1 = Warrior, 2 = Mage, 3 = Rogue
What are you? 2
A Mage. She checks your hands for ink.

What a warning looks like

Before we go on: delete the break; after case 1 on purpose and rebuild. You will meet this message for real at some point this term, so meet it now while you know exactly what caused it:

gatekeeper.cpp: In function 'int main()':
gatekeeper.cpp:15:61: warning: this statement may fall through [-Wimplicit-fallthrough=]
   15 |             cout << "A Warrior. She looks at your arms." << endl;
      |                                                             ^~~~
gatekeeper.cpp:16:9: note: here
   16 |         case 2:
      |         ^~~~

Read it as a sentence: line 15 may fall through, and here is where it falls to. Without the break, a Warrior gets the Mage line too, because a switch keeps running downward until something stops it. Put the break back. Notice that the compiler found this one for you — that is what -Wextra is buying you, and it is why zero warnings is the standard here.

Stage 2 — the decision

Now the part that matters. Add a second variable, a second question, and a three-way chain. Everything below goes after the closing brace of the switch, and int strength = 0; goes up top next to playerClass:

    cout << "Strength (0 to 100)? ";
    cin >> strength;

    if (strength >= 70)
    {
        cout << "The gate swings open. Go on through." << endl;
    }
    else if (strength >= 40)
    {
        cout << "She blocks the way. Answer me this first..." << endl;
    }
    else
    {
        cout << "She turns you around. Come back stronger." << endl;
    }

Rebuild, run, answer 3 and then 85:

1 = Warrior, 2 = Mage, 3 = Rogue
What are you? 3
A Rogue. She counts her keys.
Strength (0 to 100)? 85
The gate swings open. Go on through.

The chain runs top to bottom and stops at the first condition that's true. That is the whole mechanism, and it is also the whole trap.

Stage 3 — test the edges

No new code. This stage is the one people skip, and it is the one that finds the bug. Run your program once for each row and check the outcome against what it should be:

100 gate opens
70 gate opens — 70 counts, because the test is >=
69 riddle
40 riddle
39 turned away
0 turned away

Six runs, about a minute. The pairs are the point: 70 and 69, 40 and 39. A program that gets 100 and 0 right can still be wrong at the exact number where the rule changes, and that is where an off-by-one hides. Testing the boundary is a habit, not a step — you will do this for every condition you write from here to the capstone.
